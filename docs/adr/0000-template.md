# ADR 0000: Szablon decyzji architektonicznej

- **Status:** propozycja | przyjęta | odrzucona | zastąpiona przez ADR-XXXX
- **Data:** RRRR-MM-DD
- **Dotyczy:** moduł lub obszar z `docs/architecture.md`

## Kontekst

Co się dzieje i dlaczego trzeba podjąć decyzję. Fakty, nie preferencje:
jakie ograniczenia, jakie liczby, jakie doświadczenia z obecnego rozwiązania.

## Decyzja

Jedno zdanie w formie twierdzącej: "Robimy X".
Poniżej szczegóły, które realnie wpływają na implementację.

## Rozważane alternatywy

| Opcja | Zaleta | Wada | Dlaczego nie |
| ----- | ------ | ---- | ------------ |
|       |        |      |              |

## Konsekwencje

- Co staje się łatwiejsze.
- Co staje się trudniejsze i jaki dług przyjmujemy świadomie.
- Co trzeba zmienić w dokumentacji, migracjach albo bramkach jakości.

## Kiedy wrócić do tej decyzji

Konkretny warunek, nie "w przyszłości". Na przykład: "gdy liczba źródeł
przekroczy 50" albo "gdy dzienny koszt LLM przekroczy 20 USD".
